# Week 1 – Reflection: What tools do I need to improve before building a Laravel API?

Setting up my environment showed me that I need to improve my skills in the terminal, Git and GitHub, Postman, and the Laravel project structure.

**Terminal.** When I ran `php artisan serve`, I got "Could not open input file: artisan" because my terminal was one folder above the Laravel project. I learned that commands like `artisan`, `composer`, and `git` only work from the correct folder, so I now check my current path before running them.

**Git and GitHub.** Git was not installed on my computer at first, so none of my Git commands worked until I installed it and restarted VS Code. I also pushed from the wrong folder once and had to redo it. I learned that my Git name and email must match my GitHub account so my commits are linked to me, and that I should commit regularly with clear messages instead of uploading everything at the end.

**Postman.** I need more practice reading status codes, headers, and JSON responses, because Postman will be my main tool for testing every API endpoint.

**Laravel project structure.** I want to understand the roles of `.env`, `routes`, controllers, models, and migrations better, and how Laravel connects to MySQL through XAMPP.

This lab taught me that a working environment is the foundation of API development, and that reading error messages carefully usually points straight to the problem.
